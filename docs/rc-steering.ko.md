# RC 제어와 전륜 조향

[문서 안내](README.md) · [펌웨어 구조](firmware-architecture.ko.md) · [USB 규격](usb-protocol.ko.md)

이 문서는 현재 RC 입력, 구동 권한, 조향 보정과 모션 제한의 기준 문서다.
소스: [rc_io.cpp](../src/rc_io.cpp), [control.cpp](../src/control.cpp),
[steering_config.hpp](../include/steering_config.hpp),
[vehicle_kinematics.hpp](../include/vehicle_kinematics.hpp), [vehicle_motion.hpp](../include/vehicle_motion.hpp).

## 핀과 입력 처리

| 핀 | 역할 | 설정 |
| --- | --- | --- |
| 0 | RC 조향 입력 | CHANGE 인터럽트 |
| 1 | RC 전후 속도 입력 | CHANGE 인터럽트 |
| 2 | RC 모드 입력 | CHANGE 인터럽트 |
| 5 / 6 | 드라이버 전원 제어 | POWERDOWN에서 LOW, 그 외 HIGH |
| 9 / 10 | 왼쪽 / 오른쪽 전륜 서보 | 50 Hz, 16-bit PWM 설정 |

각 입력은 최근 유효 펄스 10개의 평균을 사용한다. 속도·조향 ISR은 **2000 µs 초과만**
거부하며 하한 검사가 없다. 모드 ISR은 800..2200 µs를 받는다. 거부되거나 새 펄스가
없으면 이전 값이 남는다. 속도·조향 필터 이력은 1500 µs지만 공개 출력의 초기값은 0이다.
모드 이력은 1200 µs, 초기 모드는 STOP이다.

속도·조향 변환 단계에서 평균을 1000..2000 µs로 제한하고, 1450..1550 µs를
중립으로 처리한다. 그 밖에서는 중립까지의 차이에서 데드밴드 50 µs를 제외한다.
MANUAL 속도는 250 µs/(m/s), 조향은 유효 입력 ±450 µs를 내륜 조향각 ±70°에 대응시킨다.
RC 입력으로 얻는 선속도 끝값은 ±1.8 m/s이며 이후 휠 RPM 제한도 적용된다.

모드, 속도, 조향은 한 시점의 원자적 스냅샷이 아니다. 루프에서 모드를 읽고 전원을
처리한 뒤 속도·조향을 읽는다. 수신기 failsafe 상태를 별도로 읽거나 펄스 갱신 만료를
판정하는 기능이 없어, RC 연결 상실을 자동 STOP으로 해석하면 안 된다.

## 제어 권한과 전원

아래 경계는 **필터 평균값** 기준이다. RC 모드와 USB의 CONTROL/BRIDGE는 별개의 상태다.

| 모드 | 평균 폭 | CONTROL에서의 구동 |
| --- | --- | --- |
| POWERDOWN | 1100 µs 미만 | GPIO 5/6 LOW, 주기 CAN 송신 중지 |
| STOP | 1100 이상 1300 µs 미만 | 구동 비활성, 주기 PID174 TQ-OFF |
| MANUAL | 1300 이상 1600 µs 미만 | RC 속도·곡률로 제어, 오류·모션 준비 조건 적용 |
| PIVOT | 1600 이상 1800 µs 미만 | 전후 입력 무시, 조향 입력으로 후륜 중심 회전 |
| AUTO | 1800 µs 이상 | 구동 차단; 호스트 timeout·estop 상태만 처리 |

MANUAL/PIVOT에서는 호스트 enable/estop 플래그와 500 ms 명령 timeout을 구동 판단에 사용하지 않는다.
AUTO에서는 유효 `0x01`을 한 번도 받지 않았거나 마지막 수신 후 500 ms를 초과하면 timeout이다.
AUTO의 호스트 속도 명령은 실제 휠 목표로 적용하지 않는다.

전원 초기화는 GPIO 5/6을 HIGH로 설정한다. POWERDOWN 진입·해제 시 디버그 세션을 취소하고
CONTROL 세션을 초기화한다. 해제 후 드라이버 시작 대기는 1000 ms다.
이 대기는 모션의 최초 시작 대기 1500 ms와 별개이며 매 전원 복귀 때 모션 전체를 재초기화하지 않는다.

BRIDGE에서는 정상 구동 스케줄이 중지되므로 RC STOP에 의한 주기 TQ-OFF도 나가지 않는다.
POWERDOWN 처리는 유지된다. 유효한 `0x01`로 CONTROL에 복귀하면 현재 RC 모드가 다시 적용되므로,
그 패킷의 속도가 0이어도 MANUAL/PIVOT의 비중립 RC 입력을 정지시키는 명령은 아니다.

## 차량 기하와 보정값

| 항목 | 현재 값 |
| --- | --- |
| 축거 | 0.420 m |
| 전륜 / 후륜 윤거 | 각각 0.439 m |
| 휠 반경 | 0.065 m |
| 조향각 범위 | ±70° |
| 좌우 서보 `inverted` / `verified` | 모두 true / true |

2026-11-09 측정값으로 등록된 **차량 조향각 → PWM** 대응은 다음과 같다.

| 차량 조향각 | 왼쪽 서보 | 오른쪽 서보 |
| ---: | ---: | ---: |
| −70° | 2100 µs | 1990 µs |
| 0° | 1577 µs | 1443 µs |
| +70° | 1044 µs | 908 µs |

테이블은 내부적으로 actuator 각도 오름차순이며, 차량 각도를 반전한 후 구간별 선형 보간한다.
따라서 헤더의 점 순서와 위 차량 각도 표의 방향이 반대다. 유효 테이블은 3..5점,
각도와 펄스가 엄격히 증가하고 중립점을 포함해야 한다. 전역 허용 펄스 범위는 500..2500 µs다.
한쪽 보정이라도 무효하면 서보 출력과 정상 구동이 차단된다. `verified=true`는 소프트웨어 설정이며
부하 상태의 실제 도달, 기구 간섭, 물리적 끝단 안전성을 새로 검증했다는 뜻이 아니다.

## 운동학과 모션 제한

MANUAL 입력은 선속도와 곡률이다. 조향 입력을 내륜 최대각으로 해석하여 곡률을 구하고,
각 바퀴 위치의 속도 벡터로 전륜 각도와 네 휠 RPM을 계산한다. 선속도 0에서도 조향이 가능하다.
PIVOT은 아래의 별도 RC 각속도 경로를 사용한다. 스키드 모드, ROS 구동 및 USB 운동학 모드 전환 요청은 없다.

| 제한 / 시간 | 현재 값 | 의미 |
| --- | ---: | --- |
| 최대 휠 속도 | 200 RPM | 필요한 경우 네 휠을 공통 비율로 축소 |
| 가속 / 감속 | 200 / 400 RPM/s | 생성 RPM의 변화율 |
| 최대 일반 조향 속도 | 180°/s | 좌우 함께 도달하도록 보간; PIVOT 고정각 지령은 예외 |
| 최초 시작 대기 | 1500 ms | 초기 중립 이동의 시간 추정 |
| 정지 후 dwell | 200 ms | 생성 RPM이 0에 도달한 뒤 대기 |
| 조향 안정 대기 | 500 ms | 목표각 도달 후 대기; 목표 변경 시 갱신 |
| 적분 시간 상한 | 0.05 s | 긴 루프 지연에 대한 모션 갱신 제한 |

상태는 STARTUP → BRAKING → STEERING → SETTLING → DRIVING 순서의 전환 절차를 사용한다.
방향 반전 등 재전환 조건이면 다시 감속·조향 절차를 거친다. DRIVING 중 조향각 변화만으로는
감속 전환하지 않는다. 실행 불가능한 목표는 전체 거부하고
휠 목표를 0으로 하며 이전 조향각을 유지한다. 실제 엔코더 기반 정지 확인이나 서보 도달 피드백은 없다.
소프트웨어의 준비·정지 추정과 물리적 정지를 구분해야 한다.

## PIVOT: 후륜 중심 회전

PIVOT은 전후 입력을 사용하지 않으며 조향 입력의 같은 데드밴드를
적용한 후 ±450 µs를 요청 각속도 ±5 rad/s에 대응시킨다. 상수는
`steering_config.hpp`의 `rc_pivot_maximum_angular_velocity`다. 공통 200 RPM 제한에 의해
실제 생성 휠 RPM은 축소될 수 있으므로 ±5 rad/s를 달성 속도로 해석하지 않는다.

회전 중심은 후륜 축 중앙이다. 전륜 지령각은 기하로 계산한
`atan2(wheelbase, front_track / 2)`의 좌측 음수·우측 양수, 현재 값으로 약 −62.4°/+62.4°다.
양의 각속도에서는 좌측 두 휠 RPM이 음수, 우측 두 휠은 양수이며 음의 각속도에서는 반대다.
전륜/후륜 속도 비율은 각 휠에서 회전 중심까지의 거리 비율로 정한다.

준비·활성 조건을 통과한 PIVOT 명령은 조향각을 **즉시 고정각으로 설정**한다.
조향 입력이 중립이어도 고정각을 유지한다. 이 지령은 180°/s 보간을 거치지 않으며,
DRIVING에서 PIVOT으로 바뀔 때도 감속·dwell 완료 전에 적용된다. 실제 서보의 즉시 도달을 뜻하지 않는다.

DRIVING 중 MANUAL↔PIVOT 전환 또는 휠 방향 반전은 BRAKING으로 전환하여 RPM 감속,
정지 dwell, STEERING/SETTLING 절차를 거친다. 이 RPM 전환 절차와 즉시 조향 지령을 구분해야 한다.
PIVOT 중립에서는 RPM 목표가 0이고 고정각은 유지된다. 최초 시작 대기, 오류 차단, RPM·가감속 제한은 공통이다.

## 오류와 정지의 의미

안전 관련 CAN TX 실패, 모터 상태 비영, 응답 누락은 driver fault를 만든다. 저전압도 구동을 차단한다.
전압 조회 TX 실패, 전압 stale, CAN overrun은 그 자체만으로 구동 차단 조건이 아니다.
여러 오류는 성공한 `0x82` 전송마다 감소하는 10회 보고 카운터를 구동 차단에도 사용한다.
따라서 오류 해제는 단순 경과시간 기준이 아니며 USB 전송 상태에 영향을 받는다.
전원 전환·CONTROL 재진입은 보고 이력을 초기화한다.

STOP/TQ-OFF는 별도 물리 브레이크가 아니다. fault만으로 GPIO 5/6을 내리거나 CAN을 재초기화하지 않는다.
사고 관측, 가능한 실패 경로, 아직 확인되지 않은 하드웨어 조건은
[조종 기능 상실 검토](rc-loss-of-control-review-2026-11-09.ko.md)를 따른다.
