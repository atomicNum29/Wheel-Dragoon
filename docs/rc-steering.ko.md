# RC 조향 입력과 임시 서보 보정

MANUAL은 좌우 스틱을 **안쪽 앞바퀴 목표각**으로 해석하고 후륜 차축 중심의 곡률
`k=1/R`로 변환한다. 제어 입력은 `RcCommand {선속도, 곡률}`만 사용한다.
**AUTO에서는 구동을 차단**한다. 기존 호스트 패킷은 수신·상태 기록만 유지하며,
ROS 각속도 조향·스키드 확장·런타임 모드 전환 API는 제거했다.

## RC 입력

수신 펄스를 1000~2000 µs로 제한한다. 1450~1550 µs는 양 끝을 포함해 중립이다.
데드밴드 밖에서는 50 µs를 빼고 남은 450 µs를 전체 조향 범위로 연속 매핑한다.

| RC 좌우 입력 | 안쪽 앞바퀴 목표각 |
| ---: | ---: |
| 1000 µs 이하 | −70° |
| 1225 µs | −35° |
| 1450~1550 µs | 0° |
| 1775 µs | +35° |
| 2000 µs 이상 | +70° |

양의 조향은 차량 좌회전 방향이다. 좌우 차등 조향을 유지하므로 양쪽 서보가 동시에
70°가 되지 않는다. 축간거리 420 mm, 전륜 윤거 439 mm에서 최대 입력은 안쪽 약 70°,
바깥쪽 약 35.4°를 요청한다. 전후 입력도 같은 클램프와 데드밴드를 사용하지만 기존
속도 스케일은 유지한다. 끝점 목표는 ±1.8 m/s이며 200 RPM 상한의 공통 비율 제한을 거친다.
클램프는 RC 신호 유실 검출이 아니며 기존 수신기 페일세이프 구조를 바꾸지 않는다.

## 운동학과 전환

`k = tan(안쪽각) / (축간거리 + 전륜 반윤거 × abs(tan(안쪽각)))`로 계산한다.
각 앞바퀴는 단위 전진 벡터 `(1∓k×전륜 반윤거, k×축간거리)`로 조향각을 구하고,
실제 선속도 `v`를 곱해 휠 속도를 결정한다. 후륜 속도는 `v×(1∓k×후륜 반윤거)`다.
따라서 정지해도 조향할 수 있고, 후진해도 같은 스틱 위치가 같은 바퀴 각도를 뜻한다.
후진 시 RPM과 차량 회전속도 부호가 반전된다. RC 조향으로 제자리 회전을 요청하지 않는다.

조향 명령의 최대 변화율은 180°/s다. 매 루프에서 양쪽의 남은 이동량 중 큰 값 `D`를
구하고 공통 진행 비율 `min(1, 180°/s × dt / D)`를 각각의 남은 각도에 곱한다.
예를 들어 60°와 30° 이동이 필요하면 각각 180°/s와 90°/s로 명령을 바꾸며 약 1/3초에
함께 목표에 도달한다. 목표가 바뀌면 현재 명령각에서 비율을 다시 계산한다. 이동량 0에서는
나누기를 하지 않으며, 마지막 단계는 양쪽 모두 목표값으로 맞춘다. 기존 dt 상한 50 ms는 유지한다.

5° 차이에 따른 감속 정책과 그 설정값은 제거했다. 주행 중 조향각 차이가 커져도
그 차이만으로 정지하지 않는다. 휠 회전 방향 반전·실행 불가능 명령의 제동과
시작/재활성화 절차는 유지한다. 이 경로의 200 ms 정지 대기 및 500 ms
안정화는 남아 있다. 동시 도달은 **명령각 기준**이며 실제 각도 피드백은 없다.

## 임시 서보 출력

RC 수신기에서 약 ±90° 구동이 가능했다는 사용자 관측을 바탕으로
**1000/1500/2000 µs ↔ −90°/0°/+90°가 선형 대응한다는 임시 가정**을 사용한다.
수신기 출력 펄스와 장착된 바퀴 각도의 관계를 측정한 값은 아니다. 이후 눈대중으로
직진 위치를 맞추고 오실로스코프로 펄스를 확인하는 방식으로 영점을 조정했다.
현재 코드의 영점은 왼쪽 1540 µs, 오른쪽 1420 µs이며 끝점은 기존 임시 값을 유지한다.

| 명령각 | 왼쪽 출력 | 오른쪽 출력 |
| ---: | ---: | ---: |
| −70° | 1889 µs | 1889 µs |
| 0° | 1540 µs | 1420 µs |
| +70° | 1111 µs | 1111 µs |

중립을 기준으로 양쪽 구간을 각각 선형 보간한다. 사용자가 확인한 장착 방향에 따라 양쪽 `inverted=true`로
설정하여 차량 각도와 PWM 증가 방향을 반전한다. 운동학/RC 각도 부호는 유지한다.
핀 9/10, 50 Hz, 16비트 PWM은 유지한다.
`verified=true`는 이번 임시 사용을 허용하는 기존 코드의 게이트이며 측정 완료를 뜻하지
않는다. 실측 후 좌우 각각의 각도·펄스·중립·반전을 수정한다. RC 입력 1000~2000 µs와
서보 출력 1111~1889 µs는 서로 다른 범위다.

영점은 각 서보 보정표의 `{0, 펄스폭}` 지점 한 곳에서 지정한다. 현재 왼쪽은
`{0,1540}`, 오른쪽은 `{0,1420}`이며 부팅 중립과 주행 중 0° 명령이 같은 값을 사용한다.
별도의 중립 펄스 필드는 없다. 보정표에는 0° 지점이 반드시 있어야 하며 펄스는
최소·최대 범위 안에서 각도 순서에 따라 증가해야 한다.

방향 반전은 `pulse_for_angle()`의 `if (c.inverted) angle = -angle;`에서 처리한다.
차량 각도를 제한한 뒤 부호를 반전하고 보정표를 조회한다. 현재 좌우 모두 true이므로
양의 차량 조향각은 보정표의 음의 각도를 사용한다. 0°는 반전해도 0°이므로 영점은 같다.

## 가감속과 확인 범위

가속은 100→200 RPM/s, 감속은 200→400 RPM/s로 변경했다. RPM 상한은 200이다.
실제 차량 가속도가 아닌 명령 RPM 변화율이며 STOP·비상정지·fault는 기존대로 램프를 우회한다.
2026-11-07 사용자는 간단한 RC 주행을 진행했고 적절한 수준으로 주행한다고 보고했다.
주행 시간·조건·로그와 업로드한 펌웨어의 정확한 커밋은 제공되지 않았으므로 정량 검증으로
해석하지 않는다. 에이전트는 이번 RC 변경에 대한 테스트·빌드·장비 업로드를 실행하지 않았다.
끝점 보정은 사용자의 결정에 따라 엔드 스톱 스위치나 엔코더 등 하드웨어를 추가한 뒤 진행한다.
현재 ±70°는 명령/임시 보정 범위이며 실제 바퀴 각도 보증값은 아니다.

## RC 전용 정리와 백업

- 최근 RC 설정, 가감속, PWM 반전, 180°/s 동시 도달, 5° 감속 정책 제거를 유지한다.
- 기존 STOP/POWERDOWN과 드라이버 fault 차단은 유지한다. AUTO는 토크 오프 경로를 사용한다.
- 이미 커밋된 CAN FIFO/ISR 수신, Windows CLI와 공통 타이밍은 유지한다.
- 조향 세부 프로브와 선택적 `0x83`, 추가 `0x82` 조향 비트는 제거했다.
  공통 타이밍은 22개 레코드이며 예약된 `steering` stage는 0이다.
  서보 출력 비용은 전체 `loop_body`에 포함되며 별도 단계로 측정하지 않는다.
- 기존 CAN CLI의 명시적 BRIDGE/benchmark 기능은 유지한다. AUTO 구동 차단은
  별도로 입력한 벤치마크 CAN 명령까지 차단한다는 의미가 아니다.
- 추가 조향 테스트/초기 설계 문서는 백업으로 옮겼다. 기존 호스트 harness의
  PWM 함수 선언만 남겼다. 백업 문서의 미커밋/미검증 표기는 정리 당시의 기록이다.
